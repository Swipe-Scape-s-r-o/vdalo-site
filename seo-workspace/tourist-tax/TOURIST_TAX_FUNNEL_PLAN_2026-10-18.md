# План воронки туристичного збору VDALO

Дата: 18 жовтня 2026 року  
Робоче середовище: гілка `staging`; production не змінюється.

## Ціль

Допомогти власнику або керівнику об’єкта розміщення перейти від пошуку місцевої ставки й розрахунку до перегляду того, як VDALO може впорядкувати щоденну роботу з даними проживання та туристичним збором. Не відволікати гостей, які прийшли лише перевірити суму.

## Принципи

1. Спочатку дати відповідь на основний намір сторінки: ставка, громада або розрахунок.
2. Пропозицію продукту чітко позначати як таку, що призначена готелям, садибам та іншим об’єктам розміщення.
3. Для міста зберігати контекст переходу й попередньо заповнювати місто на лендосі.
4. Не обіцяти автоматичне подання декларації, податкову відповідність чи встановлення права на пільгу, якщо це не підтверджено функціональністю та юридичною перевіркою.
5. Відео пояснює процес, але не блокує CTA чи форму.
6. Вимірювати не лише перегляди та кліки, а й отримані та кваліфіковані звернення.

## Сценарій користувача

### Хаб `/tourist-tax/`

Хаб і калькулятор відповідають на інформаційний запит. Після калькулятора користувач отримує довідник міст; після довідника — окремий блок для власників об’єктів з переходом на `/tourist-tax/start`. Якщо на хабі користувач обрав місто у калькуляторі, місто передається на лендос і підставляється у форму.

### Сторінки міст

Сторінка показує місцеву ставку, джерело та калькулятор. Одразу після калькулятора розміщується персональна пропозиція для об’єктів цього міста. Перехід передає населений пункт та slug міста для атрибуції.

### Лендос `/tourist-tax/start`

Коротко пояснює сценарій VDALO, показує одне з двох відео, дозволяє перейти до форми в будь-який момент. Телефон потрібен для відповіді; місто передається з попередньої сторінки; назва об’єкта — необов’язкова. Не збирати персональні дані гостей або копії їхніх документів.

## План робіт та стан

### Етап 1 — хаб

- [x] Перемістити промоблок нижче довідника міст.
- [x] Зберегти пріоритет калькулятора й пошуку ставок.
- [x] Передавати вибране місто з калькулятора у лендос без передачі кількості гостей чи інших розрахункових даних.

### Етап 2 — міські сторінки

- [x] Використовувати спільний шаблон для всіх опублікованих міст.
- [x] Зберігати місто та slug у параметрах переходу.
- [x] Показувати CTA після калькулятора й локалізувати заголовок для міста.

### Етап 3 — лендос

- [x] Розширити позиціонування на готелі, садиби та інші об’єкти розміщення.
- [x] Зробити наступну дію конкретною: обговорення робочого процесу VDALO.
- [x] Підставляти передане місто у форму; відео не є умовою для звернення.

### Етап 4 — атрибуція

- [x] Додати подію кліку на вхідний CTA з назвою джерельної сторінки, міста та позиції CTA.
- [x] Передавати сторінку входу й місто в атрибуцію звернення до CRM.
- [x] Зберегти наявні події A/B-відео, перегляду та надсилання форми.
- [ ] Підтвердити в GTM/GA4, що подія `tourist_tax_entry_cta_click` прив’язана до звіту/конверсії.
- [ ] Звіряти успішну відповідь API з фактичним отриманням ліда CRM-командою.

### Етап 5 — запуск і навчання

- [ ] На staging пройти шлях з хабу без міста, з обраним містом та з кожної тестової міської сторінки.
- [ ] Зробити одну тестову заявку лише після узгодження тестового одержувача, щоб не створювати хибного ліда.
- [ ] Після запуску порівнювати частку отриманих кваліфікованих звернень за джерелом і відеоваріантом.
- [ ] Тестувати одну змінну за раз; не оголошувати переможця лише за переглядами відео.

## Основні показники

- Перехід з хабу/міської сторінки на лендос.
- Частка CTA-кліків за містом і позицією CTA.
- Початок форми, успішне надсилання, помилка надсилання.
- Фактичне отримання ліда командою та його кваліфікація.
- Порівняння якості звернень з відео про документи/розрахунок і про квартальну звітність.
- Захисний показник: збереження використання калькулятора та переходів до довідника міст.

## Твердження та нормативні межі

Ставки туристичного збору встановлюються на місцевому рівні. Податкові агенти мають спиратися на підтверджені первинні дані; квартальне звітування та строки сплати описані ДПС. Сторінки VDALO дають довідкову інформацію та інструменти, але рішення громади й чинні нормативні акти залишаються першоджерелами.

Джерела: [стаття 268 Податкового кодексу України](https://zakon.rada.gov.ua/laws/show/2755-17#n3691), [роз’яснення ДПС щодо обчислення, декларування та сплати](https://tr.tax.gov.ua/media-ark/news-ark/1020725.html).

## Поточний релізний стан

Зміни підготовлені локально на `staging`. Production не розгортався. Пункти GTM/GA4, CRM-доставки й ручного проходження форми залишені відкритими, бо для них потрібне підключення до середовища та контрольований тестовий контакт.
