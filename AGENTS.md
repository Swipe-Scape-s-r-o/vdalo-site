# Робочі правила репозиторію VDALO

## Гілки та публікація

- Канонічний репозиторій: `Swipe-Scape-s-r-o/vdalo-site` (`https://github.com/Swipe-Scape-s-r-o/vdalo-site`), розгортається на власному сервері. Якщо локальний `origin` указує стару адресу, оновити її один раз командою `git remote set-url origin https://github.com/Swipe-Scape-s-r-o/vdalo-site.git`.
- Гілка `staging` відповідає тестовому сайту `https://staging.vdalo.tech` і захищена паролем.
- Гілка `main` відповідає живому сайту `https://www.vdalo.tech`.
- Обов’язкова послідовність кожної зміни: робоча гілка → PR у `staging` → автоматичне оновлення staging → перевірка змінених сторінок → перегляд і підтвердження Костянтина → окремий PR `staging` у `main` → перевірка основного домену.
- Сервер зазвичай оновлює staging протягом 1–2 хвилин після PR у `staging`, а основний сайт - після PR у `main`. Якщо розгортання завершується помилкою, сервер автоматично повертає попередню версію.
- Не вносити звичайні зміни сайту безпосередньо в `main`.
- Зміни на сервері й відкат автоматизовані командою, що його обслуговує. Якщо потрібне втручання в серверну конфігурацію, повідомити Олега, а не змінювати її самостійно.

## Межі коду

- `deploy/`, налаштування сервера та зв’язок форм із CRM належать команді, що обслуговує сервер. Не змінювати й не додавати туди код без окремого завдання від цієї команди.
- Тексти, дизайн, ціни та публічні сторінки VDALO можна змінювати в межах запиту користувача.
- Ключі, паролі й інші секрети мають зберігатися лише на сервері. Не додавати їх у GitHub, код, коментарі, документи чи повідомлення. Для локальної розробки використовувати лише безпечні тестові значення.
- Не вважати наявні файли Vercel джерелом поточного процесу публікації. Vercel-конфігурація може залишатися в репозиторії з попереднього хостингу; фактичну зміну інфраструктури передавати команді сервера.

## Типовий цикл зміни

1. Перевірити стан робочої теки й інструкції репозиторію.
2. Вносити зміну в окрему робочу гілку від актуального `staging`.
3. Виконати доречну локальну перевірку та переглянути diff.
4. Відкрити PR робочої гілки в `staging` і дочекатися автоматичного оновлення.
5. Перевірити відповідні сторінки на `staging.vdalo.tech`; надати Костянтину результат для перегляду.
6. Лише після підтвердження відкрити окремий PR `staging` у `main`.
7. Після автоматичного оновлення перевірити живий URL і повідомити, що саме було перевірено.

## Редакційні правила

- Не використовувати Unicode U+2014 у публічних текстах сайтів VDALO. Використовувати коротке тире U+2013 або інші доречні розділові знаки.
- Правило охоплює статті, кейси, інтерфейс, метадані, alt, JSON-LD та текст у графіці. Деталі: docs/EDITORIAL_STANDARDS.md.
- Перед збереженням нових редакцій перевіряти текст і прибирати U+2014. Не підміняти його HTML-сутністю чи CSS-кодом того самого символу.
