# Партнери та інтегратори — staging

Дата: 24 жовтня 2026. База: main/staging `84ac8f1`.

## Зміни

- Нова сторінка `/partners`: напрямки допомоги, порядок впровадження, підбір через команду, дві форми та FAQ.
- Навігація: «Про VDALO → Партнери та інтегратори» та футер «Компанія».
- Контекстне посилання зі сторінки `/integrations`; canonical, метадані й sitemap для нового маршруту.
- Заявки на підбір інтегратора та пропозиції партнерства використовують чинну audit-форму. Тип і додатковий контекст передаються в підтримуваному полі `pain`; серверні налаштування й одержувачі не змінюються.
- В аналітичні події додається лише назва варіанта форми, без введених контактів і тексту заявки. Форми позначені для маскування в Clarity.
- Немає вигаданого каталогу, сертифікації, гарантій сумісності чи безкоштовного впровадження. Обсяг, виконавець і вартість погоджуються окремо.

## Локальний огляд

- Chrome: 1440, 768, 390 і 321 CSS px, горизонтального переповнення немає.
- Переглянуто перший екран, структуру блоків і мобільне меню.
- Обидва CTA переходять до відповідних форм. FAQ і додаткові поля розкриваються.
- Порожні форми показують українські помилки і не відправляються. Назва об’єкта обов’язкова лише для підбору інтегратора; компанія у пропозиції партнерства необов’язкова. Згода початково не відмічена.
- Після прив’язки спільного обробника обидві кнопки надсилання активні. Без JavaScript є посилання на контакти.
- Синтаксис змінених JS/MJS і `git diff --check` — без помилок. Локальний набір автоматичних тестів не запускався; дві існуючі перевірки адаптовані до погодженого доповнення навігації та параметра подій.
- Помилок консолі в локальному огляді не зафіксовано.

## Межі підтвердження

Реальні заявки під час огляду не надсилалися. Налаштований production-канал був підтверджений власником у попередній роботі. Доставка нових заявок staging → CRM/Telegram і отримання подій у GA4/Clarity цим оглядом не підтверджуються. Відоме попереднє обмеження staging: окремий канал доставки не був налаштований.

Production не публікуємо: спочатку власник переглядає staging.

## Зміна погодження та стан релізу

Після затримки staging власник у цьому чаті прямо попросив перенести зміни на основний домен. PR [#78](https://github.com/Swipe-Scape-s-r-o/vdalo-site/pull/78) злитий у `main`, коміт `4037537fd582bc76a2da79d278c406c8eff75326`; staging — `c39f8f933fe1017cde0bb5260c0681764d0e1086`. На момент звірки дерева обох гілок однакові.

Фактичну публікацію сервером поки не підтверджено: `/partners` на staging і на основному домені повертає попередню 404-сторінку, на головній основного сайту ще немає нового посилання. Головна продовжує відкриватися. GitHub не має підключених CI-перевірок цього PR; результат серверних build/test/smoke недоступний. SSH-читання журналу неможливе через відсутність ключа доступу (`Permission denied (publickey)`). Серверні налаштування, одержувачі CRM і автоматичні перевірки не змінювалися.

Для завершення потрібен журнал автоматичного розгортання від команди сервера: `vdalo-site-update.service`, `/var/log/vdalo/update.log`, збірки staging `c39f8f9` і main `4037537`. Без нього причина затримки або відмови розгортання не встановлена. Злиття в GitHub не позначаємо як підтверджений живий деплой.

Знімки `local-desktop.png`, `local-desktop-forms.png`, `local-mobile.png` показують локальний макет, а не опубліковану сторінку. Реальні відправлення нових форм та отримання аналітики ще не підтверджені.
