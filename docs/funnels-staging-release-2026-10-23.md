# VDALO: оновлення 13 лендосів, 23 жовтня 2026

## База середовищ

Перед змінами виконано git fetch origin. origin/main, origin/staging та початковий HEAD однакові: 32def9c8c655191df754572eba4628a9b5c206b9. Живий /q1 на www.vdalo.tech та staging.vdalo.tech має однакові main, форму та посилання на CSS/JS. Staging доступний у звичайному Chrome; попередні помилки браузерного інструмента не є доказом несправності сайту.

Серверний SHA через SSH не підтверджено: перевірка ключа хоста не пройшла. Довіру до хоста й конфігурацію сервера не змінювали. Задокументований процес: сервер забирає GitHub staging, будує контейнер, запускає тести та smoke; main обслуговує production. Стан Git сам собою не доводить, що контейнер вже оновився: після push потрібне браузерне підтвердження нового вмісту.

Робоча гілка: codex/funnels-design-staging-oct23. Ціль поточного релізу: staging. Перенесення до main після перегляду власником.

- /q4, /q5, /qb: додано пояснення відмінності узгоджених сценаріїв відповідей від гостьового AI-помічника у розробці. Фактичний продуктовий бекенд цим оновленням не перевірявся.

- 170 автоматизованих тестів: успішно. Тести заявки використовують підставний одержувач, без реального зовнішнього надсилання.
- Валідація schema: 90/90 маршрутів, 0 помилок.
- У Chrome переглянуто всі 13 маршрутів на desktop 1440 CSS px і mobile 390 CSS px, збережено повні скриншоти у docs/design-references/oct23.
- Додатково перевірено геометрію всіх 13 сторінок на 320 і 768 CSS px. Горизонтального переповнення основного вмісту не знайдено.
- Масштаб користувацького Chrome становив 67%; розмір override підбирався за фактичним window.innerWidth, а не лише за аргументом інструмента.
- /q3: у DOM немає tax-inputs, конфігурація не містить громад для розрахунку, дві CTA відкривають спільну контактну форму. Доставлення заявки ще потребує наскрізного тесту.
- Знімки до зміни та первинний production-аудит збережені окремо.

## Перевірки staging

Статус: коміт c60731a передано в origin/staging; новий вміст підтверджено на живому staging у Chrome. origin/main залишається на 32def9c. На production /q3 досі має попередній калькулятор і не має нового макета, що підтверджує розділення середовищ.

- Усі 13 нових сторінок мають новий макет і відкриваються на staging.vdalo.tech.
- Перевірено 52 поєднання маршрут/ширина: фактичні 1440, 768, 390, 320 CSS px. Немає переповнення перевірених елементів і зламаних зображень. Дані: docs/design-references/oct23/staging-pages.json.
- Для всіх 13 перевірено: порожня назва об’єкта, перехід до контактів, непозначена згода, відсутність міста, повернення зі збереженням назви, закриття та нижня CTA. Реальних надсилань не було. Дані: docs/design-references/oct23/form-results.json.
- Усі відповіді FAQ відкриваються клавіатурою. Автоматизоване натискання мишею під час прокручування інколи потрапляло в сусідній пункт; такий результат не зараховано як доказ правильного pointer-влучання. Дані: staging-faq-keyboard.json.
- /q7: 10 × 1000 × 10% × 6 = 6000 грн; приклад 20% = 1200 грн. Дробова кількість бронювань дає конкретне пояснення про ціле число.

- Старі /q, /go/trial, /funnel, /55, /53, /54, /50, /47, /k3 відкривають відповідні незалежні сторінки. Сьогодні не повторювали всі п’ять питань старого квізу; їхній повний прохід зафіксований учорашнім аудитом, а код старого квізу не змінювався.

## Межі й окремі дії перед production

- Реальні заявки не надсилати без погодженого тестового одержувача. Наявність форми та локальний mock-тест не підтверджують доставлення до CRM.
- GTM/Clarity: у робочій області контейнера GTM-PKDT7MMT збережено одну неопубліковану зміну — призупинення дубльованого Microsoft Clarity - Official. Пряме підключення з керуванням згодою залишається. У Tag Assistant Preview на staging підтверджено: Google tag спрацював, Clarity GTM-тег призупинений; після «Лише необхідні» та перезавантаження у DOM 0 тегів clarity.ms/tag, після «Дозволити аналітику» — 1. Це підтвердження чернетки, а не опублікованої версії контейнера. Режим налагодження завершено. Докази: clarity-preview-check.json, gtm-paused-draft.jpg, tag-assistant-clarity-preview.jpg.
- Перед production потрібно опублікувати погоджену чернетку GTM та повторити перевірку згоди зі звичайною опублікованою версією. Загальний контейнер впливає на обидва домени; у цій роботі його не публікували. Фактичне надходження нового запису до інтерфейсу Clarity сьогодні не підтверджене.
- Отримання основних нових GA4-подій підтверджено DebugView. Для фінальної конверсії залишається погоджений наскрізний тест заявки.
- Фізичні iOS/Android та інші браузери не замінюються перевіркою viewport у Chrome.
- Юридичний футер головної та персональні реквізити не змінено. Значення до звіту не копіювалися.
- Файли deploy/, серверні налаштування, схема бази даних і зв’язок CRM не змінювалися.
